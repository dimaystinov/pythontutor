# PythonTutor — самостоятельный сервер

Модернизированный публичный архив PythonTutor: уроки, задачи, проверка решений,
пошаговый визуализатор, личный прогресс и кабинет преподавателя. Добавлен курс
OpenCV с загрузкой изображений, выводом результата и выдачей заданий ученикам.

- Python **3.14.7**, Django **5.2.17 LTS**.
- Среда ученика в браузере: **Python 3.14.2 / Pyodide 314.0.7**, **OpenCV 4.11.0.86**, **NumPy 2.4.6**, **Pillow 12.2.0**.
- Дополнительный серверный режим: OpenCV headless 5.0.0.93, NumPy 2.5.3, Pillow 12.3.0.
- **15 уроков, 134 задачи, 1 302 тестовые пары**.
- **8 новых задач по изображениям, 24 проверки**.
- **142 разбора**: рекомендуемое решение и альтернативы после успешной сдачи.
- Локальные JS/CSS; после сборки основные функции не требуют интернета.
- Python исполняется в браузере ученика; постоянный том SQLite хранит прогресс.

Это модернизация открытого архива, а не выгрузка производственной базы сайта.
Отличия и лицензии: [docs/PROVENANCE.md](docs/PROVENANCE.md).

## Быстрый запуск

Нужны Docker Engine/Desktop с Compose v2 и Python 3 для создания настроек.
На macOS сначала запустите Docker Desktop. Из каталога проекта:

```sh
./scripts/start.sh
```

Скрипт создаёт `.env` со случайными секретами и запускает веб-приложение.
Браузерная среда включена в проект; контейнер исполнения по умолчанию не нужен. Повторный запуск сохраняет настройки и прогресс.
Откройте **http://localhost:8042/**, изображения — **http://localhost:8042/images/**.

Эквивалентные команды и создание администратора:

```sh
python3 scripts/setup.py
docker compose up --build -d --wait --wait-timeout 180
docker compose exec web python manage.py createsuperuser
```

Пароль администратора вводится интерактивно. Ученики регистрируются на сайте.
Пользователь с `is_staff=True` может выдавать задания и смотреть результаты;
администратор назначает флаг через `/admin/`. Универсальных паролей нет,
пользователи и посылки старой демонстрационной базы не импортируются.

## Преподаватели, ученики и самостоятельная регистрация

В `/teacher/` преподаватель создаёт группу, выбирает курс и копирует ссылку
приглашения. По этой ссылке ученик видит имя преподавателя, группу и курс,
регистрируется и автоматически зачисляется. Можно также ввести код приглашения
в обычной форме регистрации. Уже зарегистрированный ученик входит по ссылке
и подтверждает присоединение. Самостоятельный переход из чужой группы запрещён:
перевод оформляет администратор. Один ученик состоит в одной учебной группе.

Кабинет позволяет добавлять учеников вручную (имя, фамилия, логин, пароль, группа),
редактировать имя/почту/группу, искать по имени, логину или почте, фильтровать
по группе и смотреть число решённых задач. Пароли не показываются в списках.
В настройках группы можно закрыть приём либо заменить приглашение, сохранив учеников.

В Django `/admin/tutorial/userprofile/` есть понятные колонки, поиск, фильтры,
редактирование имени и почты вместе с группой, кнопки кабинета и добавления ученика.
Курс синхронизируется с выбранной группой. Существующие профили при миграции
не перемещаются автоматически — администратор выбирает им группу.

Право преподавателя выдаёт администратор через `/admin/auth/user/` флагом
«Статус персонала» (`is_staff`). Не нужно выдавать права суперпользователя,
управления пользователями/правами или глобальные Django-разрешения.
Преподаватель видит только своих учеников, профили, статистику, результаты
и назначения OpenCV. Администратор (`is_superuser`) видит всех. При назначении
OpenCV пустой получатель означает всех учеников данного преподавателя.
Регистрация не может выдать себе роль преподавателя.

Ссылка строится по адресу открытого сайта. Для приглашения с другого компьютера
используйте доступный адрес сервера/домен; `localhost` относится к компьютеру
получателя. Рассылка по email не требуется: ссылку преподаватель передаёт сам.

## OpenCV и задания

Откройте «Изображения», выберите задачу и войдите. Можно использовать учебную
картинку или загрузить PNG/JPEG до **2 МиБ и 4 миллионов пикселей**.

```python
import cv2
import numpy as np
image = cv2.imread('input.png')
result = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)
cv2.imwrite('output.png', result)
```

«Запустить на изображении» показывает результат и позволяет скачать PNG.
«Проверить решение» проверяет три фиксированных входа и сохраняет прогресс.
Загруженная картинка не подменяет проверочные тесты. `cv2.imshow()` не используется:
результат сохраняется в `output.png`. Пошаговый визуализатор предназначен для
обычных Python-задач; операции OpenCV выполняются целиком. Изображения живут
только во временной среде запуска; база хранит код и результат проверки.

Преподаватель на `/images/assignments/` выбирает упражнение, ученика (либо всех
своих учеников), название, комментарий и срок. Там же видны результаты. Срок информационный,
он не блокирует позднюю сдачу. Эталоны и генератор: [image_course/](image_course/).

## База знаний после решения

Откройте `/knowledge/`. Разбор конкретной задачи доступен только после того,
как ваше решение прошло все тесты. После успешной проверки ссылка появляется
прямо под редактором. Для обычных задач и OpenCV прогресс проверяется отдельно.

В каждом разборе есть рекомендуемый вариант, другой способ, объяснение,
сложность по времени и памяти, типичные ошибки и ваше принятое решение.
Рекомендации подготовлены для этого проекта по условиям курса; это не чужие
посылки и не официальные ответы PythonTutor. Выбор учитывает читаемость и
сложность алгоритма; в сложных задачах показаны дополнительные быстрые подходы.
Разборы работают локально без внешнего ИИ/API. Автоматической персональной
оценки произвольного кода ученика нет: его можно сравнить с готовыми подходами.

Данные находятся в `knowledge/solutions/` и `knowledge/images/`, вне каталога
статических файлов. Сервер проверяет авторизацию и собственную успешную сдачу
перед выдачей разбора. Файлы доступны администратору сервера как часть исходников.
269 обычных вариантов прошли 2625 проверок на Python 3.14.7, 16 вариантов OpenCV —
48 сравнений пикселей. Отчёты и воспроизводимые проверки включены в проект.

## Перенос на сервер и HTTPS

Скопируйте проект без `.venv*`, `.git`, локальных секретов и временных файлов.
Поддерживаемые целевые архитектуры — amd64 и arm64; требуется Docker/Compose.
На новом сервере выполните быстрый запуск. Для публичного домена направьте DNS
на сервер, откройте порты 80/443 и добавьте в `.env`:

```dotenv
DOMAIN=python.example.org
ALLOWED_HOSTS=python.example.org,localhost,127.0.0.1
CSRF_TRUSTED_ORIGINS=https://python.example.org
```

```sh
docker compose -f compose.yaml -f compose.https.yaml up --build -d --wait
```

Включится Caddy с автоматическим HTTPS и защищёнными cookie. Базовый веб-порт
остаётся на `127.0.0.1`; runner наружу не публикуется. TLS-вариант требует
настоящий домен и доступ к центру сертификации. После включения HTTPS используйте
оба compose-файла при дальнейших перезапусках/обновлениях, чтобы сохранить proxy.

Для собственного reverse proxy нужны `TRUST_PROXY_HEADERS=1`,
`SESSION_COOKIE_SECURE=1`, `CSRF_COOKIE_SECURE=1`. Proxy должен сам устанавливать
`X-Forwarded-Proto`, не доверяя значению клиента; лимит тела запроса — 3 МиБ.

## Данные и эксплуатация

База находится в томе `pythontutor_tutor-data`. Миграции и импорт курса выполняются
автоматически; повторный импорт сохраняет прогресс. SQLite рассчитана на небольшую
учебную установку. Большая нагрузка требует отдельных испытаний и, возможно,
PostgreSQL. По умолчанию программы и тесты выполняются на устройствах учеников.

Только при `EXECUTION_MODE=server`: runner выполняет до четырёх программ сразу.
Код запускается без сети и root, без диска хоста, с readonly-корнем, лимитами
памяти 512 МиБ, времени и вывода. Четыре программы могут суммарно занимать около
2 ГиБ плюс память приложения. Docker socket доступен только внутреннему runner:
это привилегированная часть инфраструктуры, её нельзя открывать пользователям
или публиковать в интернете. При недоступном runner нет обходного `exec` на хосте.

Частота регистрации, входа и выполнения ограничена общей таблицей квот. За proxy
анонимные посетители разделяют его socket-IP квоту; произвольный X-Forwarded-For
не принимается.

```sh
docker compose ps
docker compose logs --tail=100 web runner
docker compose stop
docker compose up -d
```

Обновление: пересоберите worker и затем `docker compose up --build -d`.
При обновлении OpenCV проверьте эталоны; они не пересоздаются при запуске сервера.

## Резервная копия

```sh
python3 scripts/backup.py
```

SQLite backup API создаёт согласованную копию в `backups/` с правами `0600`.
Отдельно храните `.env` и исходники курса. Не используйте `docker compose down -v`,
если хотите сохранить пользователей. Восстановление заменяет текущую базу:
сначала сделайте её резервную копию, затем:

```sh
docker compose stop web
docker compose run --rm --no-deps --entrypoint python web -c \
  'import os,sys; open(os.environ["DATABASE_PATH"], "wb").write(sys.stdin.buffer.read())' \
  < backups/ВАША-КОПИЯ.sqlite3
docker compose up -d web
```

## ИИ-помощник

На страницах задач, уроков и OpenCV доступна боковая панель в стиле помощника «Зачёт»: текстовый чат, быстрые вопросы, изображения PNG/JPEG, диктовка, голосовой диалог, копирование/озвучка ответов и разворачивание панели. Чат сохраняется отдельно для каждого ученика и материала.

При отправке каждого вопроса помощник получает **актуальный, в том числе несохранённый код** из редактора, условие и статус последней проверки. Флажок «Помощник видит мой код» отключает передачу кода. Непрерывной отправки нажатий клавиш нет. До успешной сдачи системная инструкция требует подсказки вместо готовой программы; после сдачи сервер подключает проверенную статью из базы знаний. Это педагогическая настройка модели, а не гарантия отсутствия спойлеров.

Для нового сервера заполните `TUTOR_AI_*` и `TUTOR_NVIDIA_API_KEY` в `.env` по `.env.example`, затем `docker compose up -d --build web`. Ключи остаются на сервере. Основной учебник и выбранный локальный ИИ работают на устройстве; описанный в этом разделе облачный режим требует внешних API. Текущая интеграция использует Responses API NeuroRouter, NVIDIA Whisper для распознавания и NVIDIA Chatterbox для русской озвучки. Альтернативный Yandex SpeechKit включается через `TUTOR_TTS_PROVIDER=yandex` и собственный ключ.

Голосовой режим: нажать микрофон в заголовке → «Начать разговор» → разрешить микрофон. После паузы 1,4 секунды реплика отправляется; ответ звучит, затем запись следующей реплики возобновляется. Есть завершение и прерывание ответа. Закрытие панели/уход со страницы останавливает микрофон. Диктовка в текстовом режиме требует отдельной отправки распознанного вопроса. На сервере необходим HTTPS; localhost допускается браузером без HTTPS.

Ограничения: 60 вопросов за скользящие 24 часа (настраивается), 8 запросов в минуту на ученика для каждого из чата/распознавания/озвучки; реплика до 60 секунд; вопрос до 3000, код до 12000 символов; изображение до 2 МиБ и 4 млн пикселей. Показаны последние 30 диалогов, модели передаются последние 6. Аудио, снимки редактора и исходные вложения в базе чата не сохраняются; текст вопросов и ответов сохраняется и может содержать обсуждаемые фрагменты кода. Ответы появляются целиком; голосовой диалог работает по очереди, без одновременной речи. Озвучиваются первые 1800 символов, длинные листинги остаются в чате.

## Выполнение на устройстве ученика (режим по умолчанию)

`EXECUTION_MODE=browser` переносит запуск Python, пошаговую трассировку и OpenCV в Web Worker браузера. Используется локально поставляемый Pyodide 314.0.7 (CPython 3.14.2), NumPy 2.4.6, Pillow 12.2.0 и OpenCV 4.11.0.86. Стандартная библиотека и wheel-файлы находятся в `tutorial/static/vendor/pyodide`; CDN во время запуска не нужен. Первый запуск загружает примерно 14 МБ среды; графические библиотеки добавляют примерно 15 МБ и затем кешируются браузером. Документация: https://pyodide.org/en/stable/usage/webworker.html .

Сервер раздаёт сайт, тесты и файлы среды, по возможности сохраняет код/прогресс учётной записи; ученический Python на сервере не выполняется. Сравнение текстовых ответов (с допуском 1e-3) и изображений выполняется в браузере. Старые маршруты серверного запуска возвращают 409. Для ИИ и речи доступны локальный и явно выбранный облачный режимы.

Worker отделён от DOM и получает CSP с доступом только к статическим файлам движка. Сетевые запросы ученического кода к аккаунтам/API сайта запрещены. Бесконечный цикл останавливается уничтожением Worker через 8 секунд на тест; лимиты вывода/пошаговой трассы сохранены. Каждый запуск получает новую среду; файлы существуют во временной виртуальной файловой системе. Не поддерживаются системные процессы, серверная файловая система и произвольные нативные пакеты CPython. Память и скорость зависят от устройства; WebAssembly не заменяет ограничения памяти серверного контейнера.

Результат браузерной проверки не является независимой проверкой: ученик, изменивший клиент, может его подделать. `execution_source=browser` сохраняется у решения и виден в админке; прогресс и доступ к разборам работают как учебная самопроверка. Для контрольной работы можно вернуть независимый режим: `EXECUTION_MODE=server` в `.env`, собрать `runner/Dockerfile.worker` и запустить `docker compose --profile server up -d --build`.

Обычный запуск (`scripts/start.sh` или `docker compose up -d --build`) использует только веб-сервис; runner вынесен в профиль `server`. Проверка браузера: `/static/tests/browser-runtime.html` → Run checks. Старые тесты серверного режима и новые браузерного: `docker compose exec -e EXECUTION_MODE=server web python manage.py test tutorial`. Браузерные тесты сами включают новый режим.


## Установка PWA и работа полностью без сервера

Откройте `/pwa/` или кнопку «Установить приложение» в верхнем меню. «Скачать для работы без интернета» сохраняет весь курс, 142 задачи с тестами, разборы, изображения, стили и среды выполнения. «Открыть локальную версию» включает работу из кэша даже при наличии сети. «Вернуться на сайт» возвращает обычный сайт. Установка отдельного окна выполняется стандартным диалогом браузера; iOS использует меню «Поделиться» → «На экран Домой». HTTPS обязателен для публичного размещения; localhost допускается.

Service Worker хранит только отдельные публичные снимки учебных страниц и разрешённые ресурсы. HTML аккаунтов, преподавателей, админки, запросы ИИ и POST-запросы не кэшируются. Загрузка нового пакета атомарна: старый готовый пакет остаётся доступен до завершения нового. После изменения материалов обновите версию в tutorial/views/pwa.py и скачайте курс повторно. Сам Service Worker обновляется с no-cache.

Локальные решения сохраняются в IndexedDB; черновики и история чата — в localStorage. Профиль «local» отделён от вошедших пользователей. Локальные решения не переносятся автоматически в другую учётную запись. На странице PWA есть резервное копирование решений в JSON и восстановление; очистка данных сайта удаляет прогресс и скачанные модели. Офлайн-результат открывает локальный разбор. Это самопроверка: ответы и разборы физически находятся на устройстве.

Учебный Python, сравнение всех тестов, OpenCV, пошаговый визуализатор и локальные разборы не требуют запущенного Django после скачивания. Кабинет преподавателя и учётные записи требуют сервера. В онлайн-профиле отправка результата на сервер необязательна для самой проверки; при недоступности сервера результат остаётся локально.

Локальный помощник: по умолчанию Qwen2.5-Coder 1.5B, есть выбор 0.5B/7B и универсальной Qwen3 1.7B. Модель скачивается отдельно один раз. Для неё нужен WebGPU с shader-f16. Локальный голосовой ввод — Whisper tiny; офлайн-озвучка требует установленного русского системного голоса. Подробности, сравнение и источники: [docs/LOCAL_AI.md](docs/LOCAL_AI.md).
